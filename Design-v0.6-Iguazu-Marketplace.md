# IGUAZÚ MARKETPLACE — DESIGN SYSTEM VISUAL
## Versión 0.6 — Base visual refinada

> Este documento redefine la dirección visual del storefront tomando como referencia principal la captura de Home proporcionada por el usuario.
>
> La referencia define composición, proporciones, ritmo visual y jerarquía. NO se copian sus colores, tipografías ni branding.
>
> La identidad oficial de Iguazú Marketplace utiliza la paleta y tipografías indicadas en este documento.

---

# 01. CONTEXTO

## 1.1 Producto

Iguazú Marketplace es una tienda online propia especializada en:

- tecnología;
- celulares;
- informática;
- periféricos;
- audio;
- monitores;
- almacenamiento;
- componentes;
- productos relacionados.

No es una plataforma multi-vendedor.

## 1.2 Objetivo visual

La web debe sentirse como una tienda de tecnología moderna, profesional y confiable.

Debe combinar:

- estética editorial;
- simplicidad;
- amplitud;
- tecnología;
- naturaleza/Iguazú;
- identidad de marca;
- claridad comercial.

El usuario debe percibir inmediatamente que está frente a una tienda real, no a una plantilla genérica.

---

# 02. REFERENCIA VISUAL PRINCIPAL

La captura proporcionada por el usuario es la referencia principal para la Home.

Se toma de ella:

- estructura del header;
- TopBar;
- navegación horizontal;
- buscador protagonista;
- composición del Hero;
- distribución texto/imagen;
- espacios generosos;
- sección de categorías;
- product cards;
- bloques de beneficios;
- bloques promocionales;
- footer amplio;
- ritmo vertical entre secciones.

No se toman de ella:

- colores;
- tipografías;
- logo;
- textos exactos;
- fotografías;
- branding;
- valores de negocio.

La Home de Iguazú debe sentirse inspirada por esta composición, pero visualmente propia.

---

# 03. PRINCIPIOS DE DISEÑO

## 3.1 E-commerce primero

Toda decisión visual debe favorecer:

- descubrir;
- buscar;
- comparar;
- entender el precio;
- confiar;
- comprar.

## 3.2 Minimalismo con identidad

La página debe ser limpia, pero no vacía.

Evitar:

- exceso de decoración;
- exceso de bordes;
- exceso de sombras;
- exceso de gradientes;
- exceso de animación.

## 3.3 Espacio

Utilizar abundante espacio negativo.

Las secciones deben respirar.

## 3.4 Contraste

La interfaz NO debe ser completamente blanca.

Los colores de marca deben formar parte de la estructura visual, no solamente de pequeños detalles.

## 3.5 Jerarquía

El usuario debe reconocer rápidamente:

1. marca;
2. navegación;
3. búsqueda;
4. propuesta principal;
5. categorías;
6. productos;
7. beneficios;
8. acciones de compra.

# 04. PALETA OFICIAL

## 4.1 Verde profundo
`#0D3732`

Uso:
- footer;
- bloques oscuros;
- fondos de alto contraste;
- secciones institucionales;
- texto oscuro de máxima jerarquía.

## 4.2 Verde principal
`#185749`

Uso:
- títulos;
- navegación;
- acciones secundarias;
- precios;
- elementos de identidad;
- bordes y estados importantes.

## 4.3 Verde agua
`#B5E3D4`

Uso:
- superficies suaves;
- chips;
- categorías;
- fondos secundarios;
- destacados;
- estados positivos suaves.

## 4.4 Verde secundario
`#389C52`

Uso:
- acentos;
- disponibilidad;
- estados positivos;
- pequeños indicadores;
- detalles promocionales.

## 4.5 Turquesa
`#1CAAA8`

Uso:
- CTA primario;
- acciones de conversión;
- enlaces destacados;
- elementos interactivos.

## 4.6 Regla cromática

La Home debe mostrar una combinación visible de:

- superficies claras;
- verde agua;
- verde principal;
- verde profundo;
- turquesa.

No utilizar el color de forma saturada.

No reducir toda la identidad a blanco + pequeños detalles verdes.

# 05. TIPOGRAFÍA

## 5.1 Familia principal

**Mark Pro**

Archivo:
`MarkPro.ttf`

Uso:
- navegación;
- body;
- botones;
- formularios;
- metadatos;
- información de producto.

## 5.2 Familia display

**Mark Pro Narrow**

Archivos:

- `MarkPro-NarrowBold.ttf`
- `MarkPro-NarrowHeavy.ttf`

Uso:
- Hero;
- títulos;
- headings;
- grandes titulares;
- bloques promocionales.

## 5.3 Variante ligera

**Mark Pro Extlight**

Archivo:
`MarkPro-Extlight.ttf`

Uso puntual:
- textos secundarios;
- composiciones muy livianas;
- elementos de apoyo.

Nunca priorizar estética sobre legibilidad.

## 5.4 Regla tipográfica

Los títulos deben tener presencia.

Los textos secundarios deben ser cómodamente legibles.

Evitar:

- textos blancos con opacidad demasiado baja;
- tamaños excesivamente pequeños;
- pesos extremadamente ligeros en contenido funcional.

---

# 06. LAYOUT GLOBAL

## 6.1 Contenedor

Utilizar un contenedor central amplio y consistente.

La Home debe tener gutters generosos y evitar que el contenido llegue innecesariamente a los extremos.

## 6.2 Responsive

- Mobile: `< 768px`
- Tablet: `768px–1023px`
- Desktop: `>= 1024px`

## 6.3 Tablet

Tablet debe tratarse como composición propia.

Cuando una grilla o navegación deje de ser cómoda, cambiar de estructura en lugar de comprimirla excesivamente.

---

# 07. HEADER

La referencia establece un header compuesto por dos capas:

1. TopBar.
2. Navbar.

## 7.1 TopBar

Barra superior compacta.

Objetivo:
- comunicar información comercial;
- ocupar poco espacio;
- no competir con el Navbar.

Dirección visual:

- fondo verde de marca;
- texto claro;
- alto contraste;
- altura reducida;
- enlace destacado cuando exista una condición real.

No inventar promociones ni beneficios.

## 7.2 Navbar

El Navbar es un elemento principal de identidad.

Debe:

- ocupar todo el ancho;
- estar pegado al top;
- ser sólido y claramente visible;
- NO ser una pill;
- NO ser una tarjeta flotante;
- NO desaparecer;
- permanecer sticky;
- tener jerarquía clara.

Composición de desktop:

`Logo | Categorías | Buscador | Carrito | Cuenta`

## 7.3 Logo

El logo debe tener mayor presencia que en las primeras iteraciones.

Debe ser claramente reconocible sin dominar todo el header.

## 7.4 Estado sticky / scroll

Al hacer scroll:

- reducir ligeramente altura;
- reducir ligeramente padding;
- reducir mínimamente el tamaño del logo;
- mantener todos los controles funcionales;
- transición suave.

Nunca reducir tanto como para perder identidad.

## 7.5 Buscador

El buscador debe ser protagonista.

Debe tener:

- ancho suficiente;
- fondo claramente distinguible;
- icono de búsqueda;
- placeholder legible;
- estados focus y hover definidos.

No debe desaparecer visualmente en el header.

## 7.6 Carrito

Debe ser claramente identificable.

Utilizar iconografía consistente.

El badge de cantidad debe ser pequeño y visible.

## 7.7 Cuenta

Desktop:
- acceso visible;
- texto/icono claro;
- jerarquía menor que el CTA principal.

Mobile:
- simplificar;
- priorizar carrito + menú.

## 7.8 Mobile

No intentar mantener toda la navegación horizontal.

Usar:

`Logo | Carrito | Menú`

El menú debe abrirse de forma limpia y animada.

# 08. HOME — ESTRUCTURA PRINCIPAL

La Home debe utilizar una estructura modular.

Orden base:

1. TopBar
2. Navbar
3. Hero
4. Trust / beneficios rápidos
5. Categorías
6. Productos destacados
7. Bloque promocional
8. Segunda selección de productos
9. Beneficios
10. CTA de identidad
11. Footer

El orden puede ajustarse ligeramente si mejora el ritmo visual.

---

# 09. HERO

## 9.1 Composición

La composición debe seguir claramente la referencia:

### Columna izquierda
- pequeño label;
- título grande;
- descripción;
- CTA primario;
- CTA secundario.

### Columna derecha
- imagen protagonista;
- composición fotográfica limpia;
- posibilidad de formas suaves de apoyo.

## 9.2 Fondo

Preferencia:

- fondo claro;
- sensación amplia;
- contraste mediante tipografía y elementos de marca.

No convertir el Hero automáticamente en un bloque oscuro.

## 9.3 Imagen

La imagen debe tener presencia fuerte.

Puede ser:

- fotografía;
- composición de productos;
- escena tecnológica.

Debe integrarse al layout sin parecer una imagen pegada al azar.

## 9.4 Título

Debe ser grande y dominante.

Utilizar Mark Pro Narrow.

El título puede combinar:

- verde profundo;
- verde principal;
- turquesa.

La combinación de color puede utilizarse para enfatizar una palabra o fragmento.

## 9.5 Descripción

Debe ser corta.

Color de texto:
- verde oscuro o gris de alta legibilidad.

Nunca utilizar un gris demasiado claro sobre fondo blanco.

## 9.6 CTA

### Primario
`#1CAAA8` con texto blanco.

Debe ser inmediatamente visible.

### Secundario
Puede utilizar:
- blanco + borde verde;
- verde agua + texto verde profundo;
- superficie clara con contraste.

Nunca:
- texto blanco prácticamente invisible;
- borde tenue como único contraste sobre blanco.

## 9.7 Hero y Navbar

El Hero debe comenzar inmediatamente después del Navbar.

No debe existir una franja blanca accidental entre ambos.

La continuidad se consigue mediante spacing correcto, no haciendo transparente el Navbar.

---

# 10. TRUST BAR

Puede comunicar:

- envíos;
- atención;
- compra segura;
- garantía.

Debe utilizar contraste visual.

Preferencia:
- fondo verde profundo o verde agua según balance de la Home.

No inventar métricas.

# 25. 404

La página 404 debe incluir:

- mensaje;

---

# 26. MOTION

La animación debe ser sutil y funcional.

Aplicaciones:

- entrada del Hero;
- aparición de secciones;
- hover de categorías;
- hover de Product Cards;
- hover de botones;
- transición del Navbar al hacer scroll;
- apertura/cierre del menú mobile.

Características:

- rápida;
- suave;
- elegante;
- pocos píxeles de desplazamiento;
- opacidad progresiva.

Evitar:

- rebotes;
- parallax agresivo;
- zoom excesivo;
- movimientos constantes;
- animaciones decorativas sin función.

---

# 27. ICONOGRAFÍA

Mantener coherencia de:

- stroke;
- tamaño;
- peso visual;
- alineación.

No mezclar familias de iconos dentro del mismo componente.

# 28. REGLAS DE RESPONSIVE

## Mobile `<768px`

- navegación compacta;
- hero en una columna;
- imagen debajo o integrada con el contenido;
- botones cómodos para interacción táctil;
- filtros como panel;
- productos mostrados UNA CARD POR FILA;
- cada Product Card debe ocupar prácticamente todo el ancho útil disponible;
- mantener suficiente padding lateral para que la card respire;
- evitar grids de 2 columnas para Product Cards en mobile;
- no comprimir imagen, título, precio y acciones para conseguir dos columnas;
- priorizar legibilidad y comodidad táctil sobre cantidad de productos visibles simultáneamente.

### Product Cards en mobile

La referencia visual elegida utiliza una presentación vertical individual.

La card mobile debe permitir identificar claramente:

- imagen;
- favorito/badge;
- marca;
- nombre completo o con truncado controlado;
- precio;
- precio anterior cuando corresponda;
- acción principal.

La imagen debe tener espacio suficiente y conservar una proporción visual cómoda.

El contenido no debe quedar apretado verticalmente.

La acción de carrito debe ser fácil de tocar y tener contraste fuerte.

La separación entre cards debe ser visible y consistente.

## Tablet `768–1023px`

- composición propia;
- evitar comprimir desktop;
- adaptar grillas y navegación.

## Desktop `>=1024px`

- máxima riqueza visual;
- composición de dos columnas donde corresponda;
- hero editorial;
- grillas amplias;
- navegación completa.

- vendedor;
- tienda de terceros;
- publicar productos;
- vendé con nosotros;
- comisiones;
- perfil de vendedor;

- descuentos;
- métricas;
- ratings;
- tiempos de entrega;
- garantías;
- promociones.

La interfaz debe mostrar solamente información real o contenido de placeholder claramente neutro durante prototipo.

# 31. CRITERIOS DE ACEPTACIÓN DE LA HOME

La Home será considerada visualmente correcta cuando:

1. El Navbar sea visible y claramente identificable.
2. El logo tenga suficiente presencia.
3. El buscador sea visible.
4. El carrito sea visible.
5. La navegación tenga buena jerarquía.
6. No exista una separación accidental entre Navbar y Hero.
7. El Hero tenga un título fuerte y legible.
8. Los colores oficiales sean claramente visibles.
9. Los CTAs tengan contraste en estado default.
10. La Product Card permita identificar producto, precio y acción.
11. Exista ritmo visual entre secciones.
12. La Home no sea predominantemente blanca sin contraste.
13. Las animaciones sean suaves y perceptibles.
14. Desktop, tablet y mobile mantengan la identidad.
15. En mobile los productos se muestren una card por fila, con espacio suficiente.
16. No aparezcan conceptos de múltiples vendedores.

# 32. ESTADO DEL DOCUMENTO

**Versión:** 0.6

**Estado:** Nueva base visual propuesta para validación.

Esta versión reemplaza las decisiones visuales experimentales de las iteraciones anteriores cuando exista conflicto.

La v0.6 incorpora el resultado del QA visual del layout mobile de Product Cards: en pantallas menores a 768px se prioriza una presentación de una card por fila para evitar compresión y mejorar legibilidad y usabilidad táctil.

**Objetivo:** utilizar la captura de referencia como dirección visual principal de la Home, manteniendo la identidad de Iguazú Marketplace y la arquitectura real del proyecto.

La implementación debe validarse visualmente antes de considerar este Design System definitivo.
